# Helicon M2 - account plumbing Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Give Helicon per-account Muse profiles at the plumbing level: it depends on `@harjjotsinghh/aonia`, spawns one `muse serve` host per (account, workspace), records which account a session and a project belong to, and exposes REST routes to manage accounts. No UI, and with no profiles configured Helicon behaves exactly as it does today.

**Architecture:** A `hostFor(cwd, accountId?)` keyed by `${accountId ?? "default"}::${hostPathFor(cwd)}` spawns a host whose environment is `{ ...process.env, ...aonia.envFor(profile) }` when an account is chosen. `sessions.account_id` and `projects.default_account_id` are nullable additive columns (null = today's default login). aonia's `profiles.json` stays the single source of truth for the account list; Helicon stores only those two foreign ids and reads the account list live from `aonia.listProfiles()`.

**Tech Stack:** TypeScript, Node 22+, `@helicon/server` + `@helicon/daemon` (npm workspaces), `@harjjotsinghh/aonia@^0.1.0`, `node:test`. Muse SDK spawns hosts through `ServeTarget`.

**Spec:** `~/Documents/Projects/aonia/docs/SPEC.md` section 7 (Helicon integration contract) and GitHub issue HarjjotSinghh/helicon#45 sections "### 2. Helicon" and "### Then, in Helicon" (P1, P2, P5). Seam map with quoted current code: `<scratch>/helicon-m2-map.md`.

## Global Constraints

- Branch `feat/accounts-m2` off `prod`; open a PR at the end, never push to `prod`. Two other agents also push to `prod`, so rebase mentally and re-grep anchors before editing; line numbers here are from `prod` after #46 (`server.ts` 3172 lines, `HELICON_VERSION = "0.15.0"`).
- Default behaviour must not change when no account is chosen: `account_id`/`default_account_id` null everywhere, host key `default::<cwd>` must equal today's `<cwd> || "__default__"` semantics (see Task 3 for the exact keying so an existing session's host is not orphaned).
- The SDK `spawn` REPLACES the child environment; any per-profile env must be `{ ...process.env, ...aonia.envFor(profile) }` (precedent: `server.ts` native-Windows branch sets `{ ...process.env, MUSE_RELEASE_INFO }`). Passing `envFor()` alone strips `PATH` and breaks the host.
- Never read, copy, or log a Muse credential. aonia already guarantees this; Helicon only ever calls `aonia.envFor`, `listProfiles`, `getProfile`, `identityOf`, `createProfile`, `removeProfile`, `renameProfile`, `touch`, `doctor`. It never touches `auth.json`.
- No UI, client, or landing changes in M2. Do not touch `packages/ui`, `apps/web/src`, `landing/`. `SessionSummary` in the UI is unchanged; `account_id` stays server- and store-side. `POST /api/sessions` reads an optional `accountId` from the request body directly.
- Migrations are additive `ALTER TABLE ... ADD COLUMN`, nullable, appended to the existing `MIGRATIONS` array in `packages/daemon/src/store.ts`. No table rewrite, no data migration. There is NO `accounts` table (ruling: aonia is the source of truth).
- Tests: `node:test` + `node:assert/strict`, run as `npm run build && node --test "dist/test/*.test.js"` per workspace. Server tests use the `FakeConnection`/`fakeFactory`/`start()`/`send()`/`get()` harness already in `packages/server/test/server.test.ts`. Store tests use `new HeliconStore()` in memory.
- Plain ASCII in code, comments, strings, commit messages. Commit subjects sentence case, no conventional-commit prefix (repo style). No em dashes or unicode.
- Every task ends green: `npm run build --workspace @helicon/daemon --workspace @helicon/ui --workspace @helicon/server` then `npm run test --workspace @helicon/daemon --workspace @helicon/server` must pass. (`@helicon/ui` build is needed because server depends on the workspace graph; its tests are unaffected by M2.)

  /** Turns an aonia error into the right HTTP status: a duplicate is 409, a bad id or missing profile is 400. */
  private accountError(error: unknown): HttpError {
    if (error instanceof AoniaError) {
      if (error.code === "profile_exists") {
        return new HttpError(409, error.message);
      }
      return new HttpError(400, error.message);
    }
    return new HttpError(500, error instanceof Error ? error.message : String(error));
